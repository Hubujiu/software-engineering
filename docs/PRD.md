# v0.1 — 可操作的项目透视样机

## 验收目标

用户不再只能读研究报告：打开工作台，能从架构下钻到源码；发送请求，看到真实跨进程行为；从 SQL 步骤看到实际结果行；操作页面，看到调用与布局；导入自己的源码，看到不同语言的基础结构。

此版为评审样机。整体产品仍面向多语言、源码优先的全项目理解，不把 UI 演示当成全部产品。

## 首版用例

- 进入示例整体架构，展开一个进程及责任层，查阅函数正文。
- 浏览两个示例进程的启动里程碑及采集值。
- 发送 GET /members；在首次 503 场景观察一次实际等待与第二次尝试。
- 发送 POST /members；检查验证失败、真实提交及幂等重放。
- 在真实 JS 页面查看、创建成员，选择 DOM 行查看布局采样与来源。
- 查看 members/teams 模式、Member 实体、当前数据与旧请求结果快照。
- 导入 Python、Go、JS/TS 源码或 Graphify JSON；只解析，不执行。
- 导出不依赖网络的单文件评审预览，显式注明记录回放。

## 明确非目标

本轮不做任意项目自动启动，不运行上传代码；不自动识别所有框架的业务分层和隐藏决策；不提供通用 OTel/DAP、React Fiber、ORM 血缘或生产观测能力；不接入 LLM；不支持多人云平台。图谱内没有运行数据时，不播放假执行。

## 产品约束

渐进式披露的目标是减少噪声，而不是抹去副作用。静态、声明、推断与运行证据必须可区别。示例结构是示例，不得用于声称外部项目已被解析。历史行快照与当前数据库行不能混淆。表单可提交不等于证明后端幂等，因此必须跨进程验证。
